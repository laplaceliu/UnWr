# UnWr 多智能体角色矩阵

> 阶段：需求定义。本篇定义**有哪些智能体、各自做什么、怎么协作、怎么被接管**。
> 不涉及模型选型与实现方式（langgraph / 自研编排 / 单提示词切换均未定）。

---

## 一、设计原则

1. **角色即权限**：每个智能体对飞书数据的读写范围不同（如评审官只读、改稿官只写正文）。
2. **默认自动，随时接管**：主编排官默认接管调度；用户任何时候可点名某个角色直接执行。
3. **四种模式 = 角色组合 + 权限开关**，而不是四套独立系统。
4. **记忆维护是系统职责**，不是用户职责——每章写完自动沉淀摘要与状态快照。

---

## 二、角色总览

| 角色 | 代号 | 核心职责 | 写权限 | 可手动接管 | 分档 |
|------|------|----------|--------|-----------|------|
| 主编排官 | Orchestrator | 意图理解、调度、记忆维护 | 间接（通过子角色） | ✅（默认就是它） | P0 |
| 世界观设定官 | Worldkeeper | 设定词条与自洽性 | 设定表、设定文档 | ✅ | P0 |
| 人物官 | Characterkeeper | 人物档案与状态快照 | 人物表、状态表、关系表 | ✅ | P0 |
| 大纲官 | Outliner | 卷章大纲、剧情线、伏笔 | 章节表、卷表、剧情线表、伏笔表 | ✅ | P0 |
| 起草官 | Drafter | 生成章节正文 | 章节正文文档、章节表 | ✅ | P0 |
| 改稿官 | Reviser | 改写、扩缩、视角/人称/文风切换 | 章节正文文档 | ✅ | P0 |
| 评审官 | Critic | 诊断与建议（**不代笔**） | 问题表、报告文档 | ✅ | P1 |
| 救援官 | Rescuer | 卡文破局与分支生成 | 候选分支表 | ✅ | P0 |

## 三、角色详细定义

### 3.1 主编排官（Orchestrator）

| 项 | 内容 |
|----|------|
| **职责** | 理解用户意图 → 选择并调度子角色 → 汇总结果 → 触发记忆沉淀 |
| **输入** | 用户自然语言指令、当前作品上下文（作品表配置） |
| **输出** | 执行结果 + 执行过程说明（调用了谁、读了什么） |
| **触发** | 默认入口，所有未指定角色的请求 |
| **独有职责** | **分层记忆维护**：章节写完/改完后，自动生成摘要（G1）、抽取事件索引（G2）、触发人物状态快照（G3） |
| **飞书读写** | 读：作品表（模式/题材配置）；写：通过子角色间接写 |
| **接管** | 用户可随时 `@设定官`/`@改稿官` 等绕过它 |

**调度规则（意图 → 角色路由）**

| 用户意图示例 | 路由到 |
|--------------|--------|
| 「帮我想个修炼体系」 | 设定官 |
| 「沈砚这个人物立不住」 | 人物官 + 评审官 |
| 「列一下第一卷的章节大纲」 | 大纲官 |
| 「写第三章」 | 起草官（自动组装上下文） |
| 「这段太平了，改紧凑点」 | 改稿官 |
| 「帮我看看这章有什么问题」 | 评审官 |
| 「卡住了，接下来怎么走」 | 救援官 |
| 「自动写完这一卷」 | 大纲官 → 起草官（循环）→ 记忆沉淀 |

### 3.2 世界观设定官（Worldkeeper）

| 项 | 内容 |
|----|------|
| **职责** | 创建/维护设定词条；检测设定冲突；起草时提供设定注入 |
| **输入** | 用户描述、已有词条、待检查的正文片段 |
| **输出** | 结构化词条（写入设定表）、冲突报告、设定注入片段 |
| **触发** | 新建/修改设定；起草前需要设定上下文；一致性检查 H1 |
| **飞书读写** | 读/写：设定表；写：设定长文文档；读：章节正文（冲突检测） |
| **关键能力** | B1–B7；冲突检测用 `docs +fetch --scope keyword` 回溯原文 |

### 3.3 人物官（Characterkeeper）

| 项 | 内容 |
|----|------|
| **职责** | 维护人物档案；生成章末人物状态快照；检测人设崩坏 |
| **输入** | 用户描述、章节正文、既有档案 |
| **输出** | 人物档案记录、状态快照记录、崩坏检测报告 |
| **触发** | 新建/编辑人物；每章写完后生成快照；一致性检查 H2/H5/H6 |
| **飞书读写** | 读/写：人物表、人物状态表、人物关系表；写：人物小传文档；读：章节正文 |
| **关键能力** | C1–C10；状态快照是分层记忆 G3 的核心 |

### 3.4 大纲官（Outliner）

| 项 | 内容 |
|----|------|
| **职责** | 分卷分章大纲；剧情线与伏笔的埋收规划；卷章目录树维护 |
| **输入** | 作品设定、人物、已有章节、用户意图 |
| **输出** | 卷/章大纲记录、伏笔记录、剧情线记录、Wiki 目录节点 |
| **触发** | 规划新卷/新章；伏笔登记；一致性检查 H3/H4 |
| **飞书读写** | 读/写：卷表、章节表（大纲要点）、剧情线表、伏笔表、事件表；写/维护：Wiki 节点树 |
| **关键能力** | D1–D9；未回收伏笔告警走 `filter 状态=已埋设` + `sort 重要度` |

### 3.5 起草官（Drafter）

| 项 | 内容 |
|----|------|
| **职责** | 组装上下文 → 生成章节正文 → 回写索引 → 记忆沉淀收尾（摘要 / 人物状态 / 事件 / 新人物建档 / 关系登记） |
| **输入** | 本章大纲 + 相关设定 + 出场人物档案 + 前序章节记忆 + 未回收伏笔 + 题材风格配置 |
| **输出** | 章节正文文档 + 章节表索引记录（字数、状态） |
| **触发** | 用户要求写某章；自动模式批量生成 |
| **飞书读写** | 写：章节正文文档（`docs +create` / `append`）、章节表、人物状态表、人物表（仅新人物建档）、关系表（仅本章关系变化）；读：全部结构化表 |
| **约束** | 正文写入**必须文件传参**以保证换行与标题层级 ✅ |
| **关键能力** | E1–E10 |

**上下文组装顺序（E2）**：近距原文（前 K 章）> 本章大纲 > 出场人物档案+状态 > 相关设定 > 未回收伏笔 > 远期摘要

### 3.6 改稿官（Reviser）

| 项 | 内容 |
|----|------|
| **职责** | 对已有正文做定点改写，**不重写全章** |
| **输入** | 选中片段或整段、改写意图、人物档案（对白/口癖）、风格配置 |
| **输出** | 就地改写后的正文（保留其余内容不变） |
| **触发** | 用户选中文本并给出改写指令；评审官发现问题的修复 |
| **飞书读写** | 写：章节正文文档（`str_replace` / `block_replace`）；读：人物表（口癖） |
| **操作粒度** | 句/词级 → `str_replace`；段落/场景级 → `block_replace` ✅ |
| **关键能力** | F1–F10 |

### 3.7 评审官（Critic）

| 项 | 内容 |
|----|------|
| **职责** | **只诊断、不代笔**。输出问题清单与修改建议，修改动作交给改稿官或用户 |
| **输入** | 章节正文/全卷摘要、人物档案、大纲、题材配置 |
| **输出** | 诊断报告（问题 + 定位 + 建议），写入问题表与报告文档 |
| **触发** | 用户请求评审；定稿前自动检查；一致性检查 H 系列 |
| **飞书读写** | 写：检查问题表、报告文档；读：全部（**只读正文，不改正文**） |
| **关键能力** | I1–I6；可与 `drive +add-comment` 结合做段落批注 |

> **权限边界**：评审官永远不能写章节正文文档。这是它与改稿官的本质区别。

### 3.8 救援官（Rescuer）

| 项 | 内容 |
|----|------|
| **职责** | 卡文时提供多条剧情分支与破局方案 |
| **输入** | 当前章节上下文、人物状态、未回收伏笔、大纲 |
| **输出** | 多条候选分支（写入候选分支表），供用户选择 |
| **触发** | 用户明确表示卡住；起草中断 |
| **飞书读写** | 写：候选分支表；读：章节表、人物表、伏笔表 |
| **关键能力** | J1–J4 |

## 四、四种模式 = 角色组合

| 模式 | 启用角色 | 流程特征 | 人工介入点 |
|------|----------|----------|-----------|
| **协作助手** | 起草官、改稿官、救援官、设定官、人物官、大纲官 | 逐段/逐章交互，AI 出稿人改 | 每一次生成后 |
| **全自动生成器** | 大纲官 → 起草官（循环）→ 主编排沉淀记忆 | 给定题材/设定/字数，AI 自主规划并成篇 | 仅验收与微调 |
| **教练评审** | 评审官 + 设定/人物/大纲官（**只读分析**） | 不生成正文，只诊断与建议 | 全程，AI 只给意见 |
| **协作＋自动** | 默认协作模式角色；可一键触发全自动 | 日常协作，需要时一键「自动写完本章/本卷」 | 可切换 |

**模式切换** = 修改作品表「写作模式」字段，主编排官据此调整路由与权限。

## 五、手动接管协议

用户可在任意时刻指定角色接管当前任务：

| 接管方式 | 示例 | 行为 |
|----------|------|------|
| 显式 @角色 | `@改稿官 把这段改冷峻些` | 跳过主编排，直接由改稿官执行 |
| 面板选角色 | 智能体面板点选「评审官」 | 后续对话固定由该角色接管，直到切换回「自动」 |
| 选中文本 + 指令 | 选中段落 → 右键「让改稿官扩写」 | 以选中内容为作用域 |
| 切回自动 | 选择「自动编排」 | 交还主编排官 |

**接管时的上下文继承**：接管必须继承当前章节上下文（章节号、选中范围、最近对话），不能从头开始。

## 六、题材对角色行为的差异化影响

三类题材不是三套流程，而是**同一批角色 + 不同参数**（详见题材配置文档）：

| 角色 | 网文 | 类型小说 | 纯文学 |
|------|------|----------|--------|
| 大纲官 | 重节奏与爽点排布 | 重线索埋收与诡计逻辑 | 重结构张力与意象母题 |
| 起草官 | 章末钩子、短段落、快节奏 | 线索自然埋设、不露痕迹 | 语言密度、视角控制、意象复现 |
| 改稿官 | 提速、删冗余、强化钩子 | 检查逻辑漏洞与线索公平性 | 打磨语言质感、句式节奏 |
| 评审官 | 评估爽点密度与追读性 | 评估诡计公平性与自洽性 | 评估语言、叙事视角、心理深度 |
| 人物官 | 重人物标签鲜明度 | 重动机合理性与行为逻辑 | 重心理真实与弧光细腻度 |
| 设定官 | 重设定服务爽点 | **重设定自洽（最高优先级）** | 重设定的象征意味 |
