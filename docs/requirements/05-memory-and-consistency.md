# UnWr 分层记忆与一致性检查

> 阶段：需求定义。本篇定义**AI 如何记住前面写了什么**（功能点 G1–G7）
> 与**如何发现前后矛盾**（功能点 H1–H8 + 题材相关扩展项）。

---

# 第一部分：分层记忆机制

## 一、为什么必须分层

中长篇 5–20 万字，按 3000 字/章约 **70 章**。长篇连载可达数百章。

- 全部塞上下文：不可能（成本与上下文长度双重不可行）
- 只记结构化设定：正文细节全丢，人物对话的语气、场景的质感无法延续
- **分层 + 按需回溯**：近处看原文，远处看摘要，需要细节时精确取回

## 二、五层记忆模型

| 层 | 名称 | 内容 | 覆盖范围 | 注入时机 |
|----|------|------|----------|----------|
| **L0** | 活跃层 | 当前章 + 前 K 章**完整原文** | 第 N-K ~ N 章 | 每次起草 |
| **L1** | 近期层 | 章节**摘要 + 事件索引** | 第 N-M ~ N-K-1 章 | 每次起草 |
| **L2** | 远期层 | **卷级摘要** | 更早的整卷 | 每次起草 |
| **L3** | 全书层 | 全书摘要 + 人物当前状态 + 未回收伏笔 + 主线进度 | 全局 | 每次起草 |
| **L4** | 原文层 | 完整正文（不主动加载） | 全部 | **按需回溯** |

**推荐默认参数**（可配置）：`K=3`，`M=12`

### 2.1 L0 活跃层

- **内容**：当前正在写的章 + 前 3 章的完整正文
- **理由**：刚发生的事对当前写作影响最大，需要保留语气、细节、未闭合的对话
- **获取**：`docs +fetch --doc-format markdown` 逐章取回
- **存储**：章节表「正文文档」url 字段 → docx token

### 2.2 L1 近期层

- **内容**：第 N-12 ~ N-4 章的**章节摘要**（约 300 字/章）+ 事件索引条目
- **理由**：需要知道发生了什么，但不需要逐字细节
- **获取**：章节表「章节摘要」字段 + 事件表 `link` 查询

### 2.3 L2 远期层

- **内容**：更早章节按卷压缩的**卷级摘要**（约 500–800 字/卷）
- **理由**：极远期内容只需主干脉络
- **获取**：记忆索引表 `层级=卷` 的记录

### 2.4 L3 全书层（始终全量注入）

这一层体量小但**每次都要注入**，是防止"跑偏"的关键：

| 内容 | 来源 | 体量 |
|------|------|------|
| 全书摘要 | 记忆索引表 `层级=全书` | 500–1000 字 |
| **人物当前状态** | 人物状态表取每人最新一条 | 10 人 × ~80 字 |
| **未回收伏笔** | 伏笔表 `filter 状态=已埋设` `sort 重要度 desc` 取 Top 20 | 20 条 × ~30 字 |
| 主线进度 | 剧情线表 `类型=主线` | ~200 字 |
| 作品风格配置 | 作品表「风格预设」 | ~300 字 |

### 2.5 L4 原文层（按需回溯）

**触发条件**（满足任一即回溯）：

| 触发 | 示例 |
|------|------|
| 起草时人物状态摘要不足以判断 | 需要确认某次对话的原话 |
| 一致性检查命中疑似矛盾 | 需核对原文确认 |
| 用户明确引用前文 | "接第三章那场戏" |
| 改稿需要保持上下文语气 | 改写某段但需与前后文衔接 |
| 伏笔即将回收 | 需精确复现当初的措辞 |

**回溯方式**（已实机验证 ✅）：

```bash
# 按关键词精确定位，返回 hit-block-ids
lark-cli docs +fetch --doc <docid> --scope keyword --keyword "柳三娘" --as user

# 按块区间取回一段
lark-cli docs +fetch --doc <docid> --scope range --start-block-id <bid> --end-block-id <bid> --as user

# 按章节分节取回
lark-cli docs +fetch --doc <docid> --scope section --start-block-id <bid> --as user
```

## 三、上下文预算估算

以中长篇、网文预设（2500 字/章）为例：

| 层 | 内容 | 字数估算 |
|----|------|----------|
| L0 | 3 章原文 | 7500 |
| L1 | 8 章摘要 | 2400 |
| L2 | 2 卷摘要 | 1400 |
| L3 | 全书层 | 2000 |
| 设定注入（按需） | 相关词条 | 800 |
| 人物档案（本章出场） | 3 人 × 200 字 | 600 |
| 本章大纲 | — | 200 |
| **合计** | | **~15000 字 ≈ 20k token** |

> 长篇连载（数百章）体量**不随章节数增长**——因为 L1/L2 是压缩后的定长内容。
> 这是分层记忆的核心价值：**上下文成本 O(1) 而非 O(章节数)**。

## 四、记忆的生成与维护

### 4.1 触发时机

| 事件 | 动作 | 负责角色 |
|------|------|----------|
| 章节写完（状态 → 修订/定稿） | 生成章节摘要（G1）、抽取事件索引（G2）、生成人物状态快照（G3）、新人物建档与关系登记 | 起草官写章收尾当场完成（主编排官确认） |
| 章节正文被改动 | 记忆索引表「是否已过期」置真 | 主编排官 |
| 摘要标记为过期 | 重新生成摘要（G6） | 主编排官 |
| 整卷完成 | 生成卷级摘要 | 主编排官 |
| 全书过半/完成 | 生成全书摘要 | 主编排官 |
| 起草前 | 组装五层上下文（G5） | 起草官 |

### 4.2 章节摘要模板（G1）

写入章节表「章节摘要」字段（长文本已验证可存 8400+ 字 ✅）。

```
【场景】本章发生在何时何地
【事件】按顺序发生了什么（3-5 条）
【人物变化】谁的状态发生了什么改变
【新信息】本章揭示了什么此前未知的信息
【新埋伏笔】本章埋下了什么（如有）
【章末状态】章末时人物处境与未解决问题
```

固定模板的价值：**摘要可结构化比对**，支撑 H7 前后文矛盾检查。

### 4.3 人物状态快照（G3）

写入人物状态表，**（人物 × 章节）一条记录**：

| 字段 | 内容 |
|------|------|
| 所在位置 | 支撑 H5 方位矛盾检查 |
| 身体状况 | 伤势、疲劳 |
| 情绪状态 | — |
| 持有物品 | 支撑"道具凭空出现/消失"检查 |
| 关系变化 | — |
| 状态摘要 | 一句话 |

> **关键**：状态快照是**章末时点**的状态，不是人物的永久属性。
> 查询某章的人物状态 = 取该人物在 `章节号 <= N` 中最新的一条。

### 4.4 事件索引（G2）

写入事件表，每条一个事件：

| 字段 | 用途 |
|------|------|
| 事件名 | — |
| 章节 | 定位 |
| **故事内时间** | H4 时间线检查的排序依据 |
| 地点 | H5 方位检查 |
| 参与人物 | H2 人设检查 |
| 事件摘要 | G1 摘要的细化 |
| 影响 | 因果链追踪 |
| 是否关键转折 | 节奏曲线取样点 |

### 4.5 记忆存储映射

| 记忆内容 | 飞书位置 | 验证状态 |
|----------|----------|----------|
| 章节摘要 | 章节表「章节摘要」`text` | ✅ 长文本无截断 |
| 卷/全书摘要 | 记忆索引表（`层级`=卷/全书） | ⚠️ 表设计已定 |
| 事件索引 | 事件表 | ⚠️ |
| 人物状态快照 | 人物状态表 | ⚠️ |
| 过期标记 | 记忆索引表「是否已过期」`checkbox` | ✅ 字段类型可用 |
| 原文 | 章节 docx 文档 | ✅ |

# 第二部分：一致性检查

## 五、检查项清单

每项标注：**检查什么 / 数据来源 / 判定方式 / 依赖题材配置与否**

### H1 设定冲突 【P0】

| 项 | 内容 |
|----|------|
| **检查** | 正文描述与设定词条矛盾（如设定"此剑重八十斤"，正文写"他单手轻挥"） |
| **数据** | 设定表 + 本章正文 |
| **判定** | 抽取正文涉及的设定 → keyword 回溯原文 → 与词条比对 |
| **题材** | 权重由 `setting_check_weight` 控制（类型小说 0.9 / 网文 0.3） |
| **输出** | 问题表记录 + block_id 定位 |

### H2 人设崩坏 【P0】

细分为 4 个子项：

| 子项 | 检查内容 | 数据来源 |
|------|----------|----------|
| H2-a | **性格违背**：言行与性格标签矛盾 | 人物表「性格标签」+ 正文 |
| H2-b | **口癖错用**：该用口癖处未用，或不该用处用了 | 人物表「口癖」+ 对白 |
| H2-c | **动机不合理**：行为无法由核心动机解释 | 人物表「核心动机」+ 行为 |
| H2-d | **知识越界**：人物表现出其不应知道的信息 | 人物状态表（该人物在场事件）+ 正文 |

### H3 伏笔未回收 【P0】

| 项 | 内容 |
|----|------|
| **检查** | 已埋设但超过计划回收窗口仍未回收 |
| **数据** | 伏笔表 |
| **判定** | `状态=已埋设` 且 `当前章节号 > 计划回收章节号 + 容差(3章)` |
| **实现** | `record-list --filter-json '{"logic":"and","conditions":[["状态","==","已埋设"]]}' --sort-json '[{"field":"重要度","desc":true}]'` ✅ 已验证 |
| **题材** | 权重由 `foreshadow_check_weight` 控制 |

### H4 时间线矛盾 【P1】

| 项 | 内容 |
|----|------|
| **检查** | 事件时序冲突、时间跨度不合理（如"三日后"却隔了十章） |
| **数据** | 事件表「故事内时间」+ 章节表 |
| **判定** | 按故事内时间排序，检测倒序与跨度异常 |

### H5 人物方位/状态矛盾 【P1】

| 子项 | 检查内容 | 数据来源 |
|------|----------|----------|
| H5-a | **分身**：同一时点人物出现在两处 | 人物状态表「所在位置」+ 事件表 |
| H5-b | **伤势跳变**：上一章重伤，本章生龙活虎无交代 | 人物状态表「身体状况」 |
| H5-c | **道具凭空**：物品无来源地出现或消失 | 人物状态表「持有物品」 |

### H6 称谓一致性 【P1】

| 项 | 内容 |
|----|------|
| **检查** | 同一人物在文中被用不同称谓（"沈砚"/"沈兄"/"那剑客"混用导致读者困惑） |
| **数据** | 人物表「别名/称谓」+ 全文检索 |
| **实现** | `docs +fetch --scope keyword --keyword "别名1|别名2"`（支持 `|` OR 分支）✅ |

### H7 前后文矛盾陈述 【P2】

| 项 | 内容 |
|----|------|
| **检查** | 已写死的信息被推翻（第三章"他从未见过海"→ 第二十章"想起上次看海"） |
| **数据** | 章节摘要 + 事件索引 |
| **判定** | 新章节信息与历史摘要/事件做矛盾检测 |

### H8 检查报告输出 【P1】

| 项 | 内容 |
|----|------|
| **输出** | 问题清单，每条含：类型、严重度、关联章节、关联人物、定位描述（block_id）、建议 |
| **存储** | 检查问题表（已设计）+ 可选生成报告文档 |
| **阻断** | 综合分超过 `blocking_threshold` 则不建议定稿 |

## 六、题材相关扩展检查项

这些检查项**依赖题材配置**，是三类题材差异化的直接体现：

| ID | 检查项 | 依赖参数 | 网文 | 类型小说 | 纯文学 |
|----|--------|----------|------|----------|--------|
| H9 | **章末钩子缺失** | `hook_strength` | 强校验（≥4 未达标告警） | 中 | 不检查 |
| H10 | **刺激点密度不足** | `stimulus_density` | 每千字 <1.2 告警 | <0.6 告警 | 不检查 |
| H11 | **视角越界** | `pov_switch_allowed` | 禁止则检查 | 禁止则检查 | 允许，不检查 |
| H12 | **大纲偏离** | — | 中 | 高（影响诡计） | 低 |
| H13 | **字数偏离目标** | `target_words_per_chapter` | ±20% 告警 | ±25% | 不检查（允许自由） |
| H14 | **线索公平性** | `clue_fairness` | 不检查 | **强校验**（回收时线索必须已前置出现过） | 不检查 |
| H15 | **设定违规** | `rule_violation_tolerance` | `flexible` | **`none`（任何违规即报错）** | `rare` |
| H16 | **意象母题未复现** | `motif_recurrence` | 不检查 | 不检查 | **检查 motif_list 是否在本章/本卷复现** |

> H14 是推理小说的生命线：**读者在揭晓时必须能回想起线索**。
> H16 是纯文学的结构性要求：意象母题需贯穿全书。

## 七、检查执行流程

```
触发（写完一章 / 用户请求 / 定稿前）
  │
  ├─ 1. 读取本章正文 + 章节摘要
  ├─ 2. 读取人物档案（本章出场人物）
  ├─ 3. 读取相关设定词条
  ├─ 4. 读取历史记忆（L1-L3）
  │
  ├─ 5. 并行执行检查项
  │     ├─ 规则型（H3 伏笔、H4 时间线、H5 方位）：查表直接判定
  │     ├─ 语义型（H1 设定、H2 人设、H7 陈述）：需要模型判断
  │     └─ 参数型（H9-H16）：比对题材配置
  │
  ├─ 6. 需要确认时回溯原文（L4）      → docs +fetch --scope keyword ✅
  │
  └─ 7. 汇总写入检查问题表
        ├─ 严重度 = 基础分 × 题材权重 × 置信度
        └─ 综合分 > blocking_threshold → 不建议定稿
```

**规则型 vs 语义型的区别很重要**：
- 规则型**不需要模型**，查表即可，成本低、结果确定 —— 应优先做
- 语义型**需要模型判断**，成本高、有误报 —— 置信度低的应标为"建议人工确认"

## 八、MVP 建议范围

**首版必做（P0）**
- 记忆：G1 章节摘要、G3 人物状态快照、G4 原文回溯、G5 分层注入
- 检查：H1 设定冲突、H2 人设崩坏（a/b 两项即可）、H3 伏笔未回收

**首版建议加（性价比高）**
- H5-a 分身检查（规则型，查人物状态表即可，成本低）
- H6 称谓一致性（keyword 检索已验证，实现简单）
- H3 的规则型实现完全不需要模型，应优先落地

**延后**
- H4 时间线（需要故事内时间的结构化标注，依赖用户输入质量）
- H7 前后文矛盾（需要全量摘要比对，成本较高）
- H14/H16 题材专项（待题材配置完善后）
